## 文件系统基础
### 文件
- 数据项：基本数据项、组合数据项
- 记录：一组相关数据项的集合
- 文件：具有文件名的一组相关元素的集合
### 文件系统结构
- IO 控制
- 基本文件系统
- 文件组织模块
- 逻辑文件系统
### 文件逻辑结构
**无结构文件**：字节流
**有结构文件**：由一个或多个记录组成，也称记录式文件
按记录长度分类
- 定长记录：各记录长度相同，支持高效随机访问
- 变长记录：各记录长度不同，只能顺序查找
按记录的组织形式分类
- 顺序文件：分为不按 key 排序的串结构，按 key 排序的顺序结构。IO 效率最高
- 索引文件：索引表为每个记录设置索引项，包含指向该记录的指针及其长度，并按关键字排序
- 索引顺序文件：记录分组，组间暴力，组内暴力，根号平衡
- 直接文件（散列文件）：hash(key) 定位
## 目录与文件
> **文件目录**是一种数据结构，用于记录每个文件的属性、存储位置等元数据，以便在检索时快速定位其在外存中的物理地址。
### 文件控制块 FCB
每个文件对应一个FCB，包含文件名、物理位置、逻辑结构、物理结构等信息。
所有 FCB 的集合构成文件目录。
**索引节点**
- 磁盘索引节点
- 内存索引节点
inode 的核心思想：把文件名和文件描述信息分开，相当于去掉文件名之后的 FCB。
Unix 文件目录中存放：文件名 + inode 编号。
### 目录结构
- 单级：不允许重名
- 两级：用户隔离
- 树形
- 无环图：支持共享
### 文件的物理结构
**连续分配**
**链接分配**：
- 隐式链接：依赖 next 指针
- 显式链接：使用文件分配表 FAT
**索引分配**：
- 单级索引分配：每个文件有专用索引块(索引表)，分配给该文件的所有盘块号记录其中
- 多级索引分配：类似多级页表
- 混合索引分配：根据文件大小自适应采用直接寻址/单级/多级索引

| 地址类型   |             inode 地址项 | 管理数据量 | 访问路径                                |
| ------ | --------------------: | ----: | ----------------------------------- |
| 直接地址   | i.addr(0) ~ i.addr(9) |  40KB | inode → 数据块                         |
| 一级间接地址 |            i.addr(10) |   4MB | inode → 一级索引块 → 数据块                 |
| 二级间接地址 |            i.addr(11) |   4GB | inode → 二级索引块 → 一级索引块 → 数据块         |
| 三级间接地址 |            i.addr(12) |   4TB | inode → 三级索引块 → 二级索引块 → 一级索引块 → 数据块 |
### 文件的基本操作
**创建文件流程**：
1. 检查文件名是否合法、是否重名、是否有权限
2. 分配 inode / FCB
3. 分配磁盘块
4. 建立目录项
5. 更新文件系统元数据
6. 可选：打开文件并返回文件描述符
**删除文件流程**：
7. 根据路径找到目标文件
8. 检查权限、打开状态和链接计数
9. 删除目录项
10. 链接计数减 1
11. 若链接计数为 0，释放 inode / FCB
12. 释放磁盘块
13. 更新文件系统元数据
**打开文件**：
两级打开文件表：系统、进程
- 按文件路径逐级查找目录，定位目标目录项
- 从目录项中取得 inode 编号
- 在系统打开文件表中查找该 inode：
  - 若不存在：读入 inode，建立系统表项，打开计数设为 1
  - 若已存在：打开计数加 1
- 在进程打开文件表中建立新表项，指向系统打开文件表项
- 返回进程打开文件表项的索引，即文件描述符
- **后续读写通过文件描述符完成**
> 链接的查找速度通常优于软链接
### 文件保护
- ACL：读、写、删、执行，创建者、组、其他
- 口令：安全性弱
- 加密：安全性强，开销大
## 文件系统
### 磁盘布局
MBR、分区表、各分区。其中，每个分区含有：
- 引导块
- 超级块
- 空闲块信息
### 内存布局
- 挂载表
- 目录项缓存
- 系统级打开文件表
- 进程级打开文件表
### 对空闲区域的管理
- 空闲表法：分配策略与内存动态分区分配一致
- 空闲链表法：空闲盘块链 / 空闲盘区链，前者单盘块分配简单但效率低开销大，后者相反
- 位视图法
- 成组链接法：空闲块按组管理，超级块存当前一组空闲块号，每组中特殊块保存下一组空闲块号
### 虚拟文件系统 VFS
提供四种核心抽象：
- 超级块对象
- V 节点对象
- 目录项对象
- 文件对象
### 挂载
> 如同文件在使用之前必须先打开一样，文件系统在被进程访问前也必须先安装，也称挂载(Mounting)。将某个设备上的文件系统挂载到目录树中的一个目录后，即可通过该目录访问该设备上的文件。
