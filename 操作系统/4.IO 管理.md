## 输入/输出管理
### I/O 管理概述
> I/O 管理的核心目标：管理各种外部设备，屏蔽设备差异，协调 CPU、内存和设备之间的数据交换，提高 CPU 与设备的并行性。

### I/O 设备
**I/O 设备**：用于完成输入、输出或存储功能的外部设备。

按信息交换单位分类：
- 字符设备：以字符为单位传输，如键盘、鼠标、打印机、终端
- 块设备：以数据块为单位传输，如磁盘、SSD、U盘

按传输速率分类：
- 低速设备：键盘、鼠标
- 中速设备：打印机
- 高速设备：磁盘、网卡

按共享属性分类：
- 独占设备：同一时刻只能被一个进程使用，如打印机
- 共享设备：可被多个进程并发访问，如磁盘
- 虚拟设备：通过 SPOOLing 等技术把独占设备改造成逻辑共享设备

### I/O 接口
> CPU 不直接控制具体设备，而是通过 I/O 接口，也称设备控制器，间接控制设备。

设备控制器的作用：
- 接收 CPU 发来的 I/O 命令
- 控制具体设备执行操作
- 完成设备与内存 / CPU 之间的数据交换
- 向 CPU 报告设备状态
- 缓冲数据，协调速度差异
- 进行差错检测

设备控制器的组成：
- CPU 与控制器接口
- 控制器与设备接口
- I/O 逻辑

设备控制器常见寄存器：
- 数据寄存器：暂存输入 / 输出数据
- 控制寄存器：接收 CPU 发来的控制命令
- 状态寄存器：记录设备当前状态，如忙、空闲、出错

### I/O 控制方式
> I/O 控制方式解决的问题：一次 I/O 操作中，CPU 需要参与多少。

发展方向：
- CPU 参与越来越少
- 设备与 CPU 并行程度越来越高
- I/O 效率越来越高

**程序直接控制方式**：
- 又称轮询方式
- CPU 发出 I/O 命令后，不断查询设备状态
- 设备准备好后，CPU 进行数据传输
- 优点：实现简单
- 缺点：CPU 一直等待，利用率低
- 特点：CPU 和 I/O 设备串行工作

流程：
1. CPU 向设备控制器发出 I/O 命令
2. CPU 不断检查设备状态
3. 设备就绪后，CPU 读 / 写数据
4. 重复上述过程，直到 I/O 完成

**中断驱动方式**：
- CPU 发出 I/O 命令后，可以转去执行其他进程
- 设备完成 I/O 后，通过中断通知 CPU
- CPU 执行中断处理程序
- 优点：CPU 不必一直轮询，利用率提高
- 缺点：数据仍要经过 CPU 寄存器，且 CPU 按字节 / 字为单位干预
- 适合：字符设备、小数据量传输

流程：
1. CPU 发出 I/O 命令
2. 请求 I/O 的进程阻塞
3. CPU 调度其他进程运行
4. 设备完成 I/O 后发出中断
5. CPU 执行中断处理程序
6. 唤醒等待 I/O 的进程

**DMA 方式**：
> DMA：Direct Memory Access，直接存储器访问。

核心思想：在 I/O 设备和内存之间建立直接数据通路，数据传输不再经过 CPU。

DMA 特点：
- 基本传输单位是数据块
- 数据直接在设备和内存之间传输
- CPU 只在传输开始和结束时参与
- 适合高速块设备，如磁盘

DMA 控制器主要寄存器：
- CR：命令 / 状态寄存器
- MAR：内存地址寄存器，记录内存起始地址
- DR：数据寄存器，暂存单次传输数据
- DC：数据计数器，记录剩余传输字节数

DMA 工作流程：
1. CPU 设置 DMA 控制器参数
2. CPU 启动 DMA
3. CPU 转去执行其他任务
4. DMA 控制器接管总线
5. 设备和内存直接传输数据块
6. 传输完成后，DMA 向 CPU 发中断

**通道控制方式**：
> 通道是一种专用 I/O 处理机，可以执行通道程序，负责复杂 I/O 控制。

特点：
- CPU 只需发出一条 I/O 指令
- 通道根据通道程序完成后续 I/O 操作
- 可管理多台设备
- CPU、通道、I/O 设备可以并行工作
- 比 DMA 更进一步减少 CPU 干预

DMA 与通道区别：

| 对比项 | DMA | 通道 |
|---|---|---|
| 本质 | 控制器 | 专用 I/O 处理机 |
| 控制方式 | CPU 预设参数 | 执行通道程序 |
| 管理能力 | 通常较简单 | 可处理复杂 I/O |
| 设备数量 | 通常服务一个设备 | 可管理多台设备 |
| CPU 干预 | 开始和结束参与 | 只需启动通道程序 |

I/O 控制方式总结：

| 控制方式 | CPU 参与程度 | 数据传输单位 | 特点 |
|---|---|---|---|
| 程序直接控制 | 最高 | 字 / 字节 | CPU 轮询，效率低 |
| 中断驱动 | 较高 | 字 / 字节 | 设备完成后通知 CPU |
| DMA | 较低 | 数据块 | 设备和内存直接交换 |
| 通道 | 最低 | 一组 I/O 操作 | 专用处理机控制 I/O |

### I/O 软件层次结构
从上到下：
- 用户层 I/O 软件
- 设备独立性软件
- 设备驱动程序
- 中断处理程序
- 硬件

**用户层 I/O 软件**
- 面向用户程序
- 提供库函数或系统调用封装
- 如 printf、scanf、read、write 等

**设备独立性软件**
> 设备独立性软件位于设备驱动程序之上，负责屏蔽设备差异，向上提供统一 I/O 接口。

主要功能：
- 提供统一的驱动程序接口
- 设备命名
- 设备保护
- 缓冲管理
- 差错控制
- 独占设备的分配与回收
- 统一数据块大小

**设备驱动程序**
> 驱动程序直接面向具体设备控制器，把上层抽象 I/O 请求转换成设备能识别的具体命令。

主要功能：
- 接收上层 I/O 请求
- 检查请求合法性
- 设置设备控制器寄存器
- 启动设备
- 处理设备状态
- 完成具体硬件控制

**中断处理程序**
> 中断处理程序负责响应设备发来的中断，是最靠近硬件的软件层。

主要功能：
- 保存被中断进程现场
- 判断中断来源
- 读取设备状态
- 处理传输完成事件
- 唤醒等待 I/O 的进程
- 恢复现场或触发调度

注意：
- 中断处理程序执行结束后，不一定回到原进程
- 若唤醒了更高优先级进程，可能发生进程切换

### 应用程序 I/O 接口
应用程序通过统一接口访问设备，不直接操作具体硬件。

**字符设备接口**
- 面向字符设备
- 以字符流为单位传输
- 一般不可随机访问
- 典型设备：键盘、鼠标、打印机、终端
- 常见操作：get、put、打开、关闭、控制

**块设备接口**
- 面向块设备
- 以数据块为单位传输
- 支持随机访问
- 典型设备：磁盘、SSD、U盘
- 常见操作：read、write、seek

**网络设备接口**
- 面向网络通信设备
- 通常通过 Socket 接口访问
- 通信对象可以是远程主机上的进程
- 常见操作：socket、bind、listen、accept、connect、send、recv、close

### 阻塞 I/O 与非阻塞 I/O
**阻塞 I/O**
- 进程发起 I/O 请求后，若数据未就绪，则进入阻塞态
- I/O 完成后，进程被唤醒并进入就绪态
- 优点：不会空转浪费 CPU
- 缺点：等待期间进程不能继续执行

流程：
1. 进程发起 I/O 请求
2. 数据未准备好
3. 进程阻塞
4. 设备完成 I/O
5. 中断处理程序唤醒进程
6. 进程重新进入就绪队列

**非阻塞 I/O**
- 进程发起 I/O 请求后，若数据未就绪，系统立即返回
- 进程可以继续执行其他任务
- 优点：进程不会被挂起
- 缺点：若反复查询，会浪费 CPU

## 设备独立性软件
### 设备独立性
> 设备独立性指应用程序使用逻辑设备名访问设备，而不关心实际物理设备。

好处：
- 屏蔽设备差异
- 提高程序可移植性
- 便于设备替换
- 便于统一管理设备
- 便于实现设备分配和保护

逻辑设备名与物理设备名：
- 逻辑设备名：用户程序看到的设备名
- 物理设备名：系统内部实际设备名
- 系统通过映射表把逻辑设备名转换为物理设备名

### 高速缓存与缓冲区
**高速缓存 Cache**
- 保存慢速设备上已有数据的副本
- 主要目标：提高重复访问效率
- 命中时可避免访问低速设备
- 数据可长期存在，直到被替换

**缓冲区 Buffer**
- 保存正在传输过程中的数据
- 主要目标：协调速度差异，提高并行性
- 数据传输完成后通常释放
- 常用于 CPU 与设备、设备与设备之间

高速缓存与缓冲区对比：

| 对比项 | 高速缓存 Cache | 缓冲区 Buffer |
|---|---|---|
| 位置 | 高速设备和低速设备之间 | 高速设备和低速设备之间 |
| 存放内容 | 慢速设备中已有数据的副本 | 正在传输的数据 |
| 主要目的 | 提高重复访问效率 | 协调速度差异，提高并行性 |
| 生命周期 | 可长期驻留 | 传输完成后通常释放 |
| 典型作用 | 减少低速设备访问次数 | 降低等待和中断频率 |

### 缓冲技术
引入缓冲区的原因：
- 缓和 CPU 与 I/O 设备速度不匹配
- 减少 CPU 中断频率
- 提高 CPU 与设备并行性
- 解决数据粒度不匹配问题

**单缓冲**
- 系统只设置一个缓冲区
- 输入设备先把数据送入缓冲区
- CPU 再从缓冲区取数据处理
- 可提高一定并行性，但效果有限

**双缓冲**
- 系统设置两个缓冲区
- 一个缓冲区输入数据时，另一个缓冲区可供 CPU 处理
- 比单缓冲并行性更好
- 常用于生产者和消费者速度接近的场景

**循环缓冲**
- 多个缓冲区首尾相连形成循环队列
- 适合连续输入 / 输出
- 通过输入指针和输出指针管理缓冲区

**缓冲池**
> 缓冲池由多个缓冲区组成，统一管理空缓冲、输入缓冲和输出缓冲。

缓冲池中的队列：
- 空缓冲队列
- 输入队列
- 输出队列

缓冲池常见操作：
- 收容输入：设备输入数据到空缓冲区，装满后挂入输入队列
- 提取输入：计算进程从输入队列取数据，处理完后归还空缓冲队列
- 收容输出：计算进程把输出数据写入空缓冲区，装满后挂入输出队列
- 提取输出：输出进程从输出队列取数据输出，完成后归还空缓冲队列

### 设备分配与回收
> 设备分配是指系统根据用户 I/O 请求，为进程分配所需设备、控制器和通道。

设备分配目标：
- 提高设备利用率
- 避免设备竞争冲突
- 避免死锁
- 保证设备访问安全

设备分配相关数据结构：
- 设备控制表 DCT：记录每台设备的信息
- 控制器控制表 COCT：记录每个控制器的信息
- 通道控制表 CHCT：记录每个通道的信息
- 系统设备表 SDT：记录系统中全部设备的信息

设备、控制器、通道关系：
- 一个通道可连接多个控制器
- 一个控制器可连接多个设备
- 设备分配时可能需要同时分配设备、控制器和通道

设备分配过程：
1. 根据逻辑设备名查找系统设备表
2. 找到对应设备控制表
3. 判断设备是否空闲
4. 若设备空闲，则分配设备
5. 分配对应控制器
6. 分配对应通道
7. 建立逻辑设备到物理设备的映射
8. 启动 I/O 操作

设备分配策略：
- 静态分配：进程运行前一次性分配所需设备，运行结束后释放
- 动态分配：进程运行过程中按需申请设备，使用完立即释放

静态分配：
- 优点：不会发生死锁
- 缺点：设备利用率低

动态分配：
- 优点：设备利用率高
- 缺点：可能发生死锁

### SPOOLing 技术
> SPOOLing 又称假脱机技术，用磁盘上的输入井和输出井模拟脱机输入 / 输出，把独占设备改造成逻辑共享设备。

SPOOLing 组成：
- 输入井：磁盘上模拟输入设备的区域
- 输出井：磁盘上模拟输出设备的区域
- 输入缓冲区：内存中暂存输入数据
- 输出缓冲区：内存中暂存输出数据
- 输入进程：负责把输入设备数据送入输入井
- 输出进程：负责把输出井数据送到输出设备

SPOOLing 特点：
- 以磁盘空间换设备并行性
- 提高独占设备利用率
- 将独占设备改造成虚拟共享设备
- 典型应用：打印机共享

打印机 SPOOLing 流程：
1. 用户进程请求打印
2. 系统不直接占用打印机
3. 先把打印数据写入磁盘输出井
4. 为该打印任务建立请求项
5. 输出进程按队列顺序取出打印任务
6. 真正驱动打印机输出

SPOOLing 本质：
- 用户以为自己独占打印机
- 实际上只是把输出数据放入磁盘队列
- 打印机由后台输出进程统一调度

### 设备驱动程序接口
设备驱动程序的上层接口：
- 向设备独立性软件提供统一调用方式
- 屏蔽不同设备控制器的差异

设备驱动程序的下层接口：
- 面向具体设备控制器
- 操作设备寄存器
- 发送设备命令
- 接收设备状态

驱动程序的核心作用：
- 把抽象 I/O 请求转换为具体硬件操作

## 磁盘和固态硬盘
### 磁盘结构
磁盘由多个盘片组成，每个盘片有两个盘面，每个盘面有若干磁道，每个磁道分为若干扇区。

基本概念：
- 盘面：磁盘表面，用于存储数据
- 磁道：盘面上的同心圆
- 扇区：磁道上的固定大小区域，是磁盘读写的基本单位
- 柱面：所有盘面上半径相同的磁道组成一个柱面
- 磁头：负责读写盘面数据

磁盘地址通常包括：
- 柱面号
- 磁头号
- 扇区号

磁盘读写过程：
1. 寻道：磁头移动到目标磁道
2. 旋转延迟：等待目标扇区转到磁头下方
3. 数据传输：读出或写入数据

### 磁盘存取时间
一次磁盘 I/O 时间由三部分组成：
- 寻道时间：磁头移动到目标磁道的时间
- 旋转延迟时间：目标扇区旋转到磁头下方的等待时间
- 数据传输时间：实际读写数据的时间
