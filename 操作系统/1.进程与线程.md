## 进程
**进程映像**由程序段、相关数据段、PCB 构成。
创建进程的本质是创建其PCB。
进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位。
特征：动态性、并发性、异步性、独立性

PCB 的组织方式有：
- **链接方式**：不同状态的进程放在不同的队列中
- **索引方式**：为每种状态建立索引表，表项指向对应状态的PCB
程序段可被不同进程共享，但数据段相互独立。

程序被加载运行时，OS 会为其建立一个**虚拟地址空间**，包含：
- 代码段：`.init` `.text` `.rodata` 存放指令和只读数据
- 数据段：`.data` `.bss` 分别存放已/未初始化的全局和静态变量
- 堆：低位向高位增长
- 栈：高位向低位增长

**进程的状态与转换**：
运行态、就绪态、阻塞态、创建态、终止态。
其中，创建态只短暂存在，终止态进程不会参与调度，但 PCB 等信息会短暂保留。

**进程的创建**：
操作系统通过**创建原语**创建新进程，步骤如下：
- 分配唯一标识并申请 PCB
- 分配新进程所需的资源
- 初始化 PCB（通常优先级最低）
- 插入就绪队列

**进程的终止**：
操作系统通过**终止原语**完成进程的撤销，步骤如下：
- 根据被终止进程的标识符，检索其PCB，并读取当前状态
- 若该进程正处于运行态，立即剥夺其CPU，并触发调度程序选择下一个就绪进程
- 释放该进程占用的所有系统资源，统一归还给操作系统
- 若系统支持**级联终止**，则递归终止其所有子孙进程；否则，子孙进程继续运行
- 将该进程的PCB从所在队列/链表中移除，完成清理

**阻塞原语**：
- 保存当前进程的CPU现场(如程序计数器、状态寄存器等)到其PCB中
- 将其PCB中的状态字段修改为阻塞态，并将该PCB插入所等待事件的等待队列中
- 调用调度程序，从就绪队列中选择另一个进程投入运行，以释放CPU资源

**唤醒原语**：
- 指定事件的等待队列中找到目标进程的PCB
- 将其从等待队列中移出，并将状态置为就绪态
- 将该PCB插入就绪队列，等待调度程序在适当时机选中并恢复其执行

## 进程的通信
可分配**低级通信**和**高级通信**。前者一般是PV操作等控制信息，后者是大量数据。
高级通信主要包括：

**共享存储**：
通过特殊的系统调用，创建一段独立的内存区域，并将其映射到多个进程的虚拟地址空间中，使这些进程都能直接读/写该区域。
对于同一片内存，必须引入同步互斥机制，且 OS 不自动提供这种保护。

**消息传递**：
- **直接通信方式**：发送进程通过发送原语将消息发给指定的接收进程；内核负责将消息从发送方复制到接收方的内核缓冲队列中；接收进程通过接收原语接收消息，
- **间接通信方式**：通信双方不直接指定对方，而是通过一个中间实体(通常称为信箱)进行消息交换。发送进程将消息投递到信箱，接收进程从信箱中取出消息。

**管道通信**：
基于先进先出原则的进程间通信机制，常用于具有亲缘关系的进程。经由操作系统内核维护的一块固定大小的内存缓冲区。
为保证正确性，管道机制必须提供：
- 互斥：同时仅一个进程可以读写管道
- 同步：管道满时，写进程阻塞，等待读出
- 写端关闭检测

**信号**：
用于通知进程某个事件已发生的机制。
## 线程和多线程
> 引入线程是为了进一步降低程序并发执行时的时空开销，提升 OS 并发性能。

线程可被通俗地理解为“轻量级进程”，它是程序执行流的最小单元，也是处理器调度的基本单位。

同一进程的所有线程共享代码段、数据段、堆、文件描述符等系统资源，可并发执行相同的代码。

进程是系统资源分配的基本单位，线程是独立调度的基本单位。线程不拥有独立的系统资源。

**TCB 包含**：
- 线程标识符 TID
- 寄存器集合
- 现成当前状态（三种）
- 调度优先级
- 线程局部存储区
- 堆栈指针
每个线程拥有独立的私有栈，但都位于进程的地址空间内，理论可以互相访问修改，但应避免。

按照实现方式，线程可以分为：

**1. 用户级线程 ULT**
线程管理和调度在用户态进行，内核不可感知。
优点：调度策略由应用程序定制；线程切换不进入内核态，开销小；实现与 OS 无关，好移植。
缺点：系统调度仍以进程为单位，一个现成阻塞则整个进程挂起；无法多核并行。

**2. 内核级线程 KLT**
线程管理和调度在内核态进行，内核通过 TCB 感知。
优点：多核并行；阻塞处理灵活；内核自身通过多线程提高并发性能。
缺点：线程切换需陷入内核态，开销大。

**3. 组合方式**
根据 ULT 与 KLT 的映射关系，可以分为：
- 多对一：切换效率高，但阻塞和并行困难
- 一对一：支持并行，但系统开销大（TCB、调度）
- 多对多：优点兼具

**线程库实现**：
主流：POSIX Pthreads、Windows线程API、Java线程API
- 纯用户空间实现
- 内核支持实现

> 外存中的作业
> ↓ 高级调度
> 内存中的就绪进程
> ↓ 低级调度 / 进程调度
> CPU 上运行
## CPU 调度
CPU 调度分为：
- **高级调度**（作业调度）：硬盘加载到内存
- **中级调度**（内存调度）：换入/换出内存
- **低级调度**（进程调度）：分配 CPU

调度程序含有：
- **排队器**
- **分派器**
- **上下文切换器**

在**处理中断**或**执行原子操作**过程中，不能进行进程调度。

**调度算法衡量标准**：
- CPU 利用率：工作时间 / (工作时间 + 空闲时间)
- 系统吞吐量：单位时间完成作业数量
- 周转时间：作业从提交到完成的总时间
![[Pasted image 20260528162654.png|511]]
- 等待时间：进程在就绪队列中等待 CPU 的总时间
- 响应时间：用户提交请求到系统首次产生响应所经历的时间
> 时钟中断不一定导致上下文切换。它一定会进入中断处理程序，通常会触发调度检查，但只有当当前进程需要让出 CPU 时，才会发生上下文切换。

调度算法分为：
- FCFS（非抢占）：实现简单，效率低
- SJF（可抢占）：对长作业不利（饥饿），忽略紧迫度
- 高响应比优先（不可抢占）：响应比 = (等待时间 + 估计运行时间) / 估计运行时间，避免了饥饿
- 优先级（可抢占）：分为静态/动态
- 时间片轮转：时间片大小很重要
- 多级队列：不同队列采用不同调度算法，队列本身可有优先级
- 多级反馈队列：就绪进程分到多个优先级队列中，根据进程是否用完时间片动态升降级
- 保证：每个进程 CPU 时间相同
- 公平分享：每个用户 CPU 时间相同

**多处理机调度**：
分为非对称 AMP 和对称 SMP。
SMP 有两个核心矛盾：
- 处理器亲和性：进程跨 CPU 迁移需重填缓存，代价高，所以应尽量避免迁移
- 负载平衡：通常会抵消处理器亲和性带来的好处

**多处理机调度方案**：
- 公共就绪队列：软亲和、硬亲和
- 私有就绪队列：推迁移、拉迁移
## 同步与互斥
对临界资源的访问必须以互斥方式进行。在每个进程中，访问临界资源的那段代码称为临界区。
**原则**：
- 空闲让进
- 忙则等待
- 有限等待
- 让权等待

**软件实现方法**：
- 单标志法：必须交替进入，违反空闲让进
- 双标志先检查法：违反忙则等待
- 双标志后检查法：违反空闲让进、忙则等待，可能饥饿
- Peterson 算法：忙等

**硬件实现方法**：
- 中断屏蔽方法：限制并发、不安全、不适用多处理器系统
- 硬件指令方法 - TS 原子操作：忙等
- 硬件指令方法 - Swap 指令：忙等

**互斥锁（自旋锁）**：忙等，原子操作，需要硬件支持

**信号量**：可用于实现互斥锁和同步
- 整型信号量
- 记录型信号量：不忙等（实现让权等待）

- 消费者-生产者问题
- 写者-读者问题

**管程**：
操作系统中的静态资源管理模块，仅供进程调用。
**条件变量**：
不同的阻塞原因分别抽象为独立的条件变量，每个条件变量维护一个等待队列。
这里的成员函数不是新线程；函数是线程进入管程后执行的代码。
线程是主动调用这些函数的执行实体。
任一时刻，最多只有一个进程能够在同一管程内执行。
```c
monitor Demo {
    int S;
    condition x;
    init_code() {
        S = 5;
    }
    void take_away() {
        if (S <= 0) {
            x.wait();
        }
        S--;
        // 分配资源，做一系列相应处理
    }
    void give_back() {
        // 归还资源，做一系列相应处理
        S++;
        if (/* 有进程在等待 */) {
            x.signal();
        }
    }
}
```
## 死锁
指多个进程因竞争资源而陷入相互等待的僵局。

死锁的发生必须同时满足：
- 互斥
- 不可剥夺
- 请求并保持
- 循环等待

处理死锁：
- 预防：严格限制四个条件同时达成
- 避免：分配前检测是否可能死锁
- 检测及解除：定期检测解除

系统安全状态
**银行家算法**：
- 合法性检查
- 资源可用性检查
- 试探性分配
- 安全性检查

**资源分配图**：
对于可执行的进程，删除所有出入边。
**死锁定理**：
系统处于死锁状态，当且仅当其资源分配图不可完全简化。
